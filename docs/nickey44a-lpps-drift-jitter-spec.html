nickey44a LPPS — ドリフト対策・ジッタ対策

対象リポジトリ: conta999-dot/zmk-config-nickey44a ブランチ lpps
参照コミット: 7aaded75a48a9042171f4969ed1b1988106ea803（ストリーム方式）

概要

SK8707 を搭載した LPPS ドライバは、1 回の IRQ ごとに主に ±1 のパルス列で移動量を表します。 本キーボードでは左半分（peripheral）と右半分（central）のそれぞれに LPPS があり、 左の生入力は BLE split で中央に届き、中央の input processor チェーンを通って HID に送られます。

ジッタ対策の目的

触っていないときのランダムな ±1 や、符号がばらつく微小振動をカーソル・レイヤー4に届かせないこと。

ドリフト対策の目的

一方向に流れ続けるセンサバイアスや、打鍵振動に乗った誤報告、レイヤー4の誤保持を抑えること。連続の±1 ストリーム（意図した操作）は通す。

ジッタ と ドリフト は層が異なります。 大半の閾値処理は各半分のファーム内 zmk-driver-lpps/src/lpps.c で、 レイヤー4や打鍵ロックアウトは中央（右）ファームの input processor で行います。

信号経路

[ LPPS I2C @0x57 ] ──IRQ──► lpps.c（各半分）
                              │ N 未満は非報告、N 到達後ストリーム
                              ▼
        左: zmk,input-split ──BLE──► 中央 left_pointing_listener
        右: pointing_listener（同一 SoC）
                              │ zip_left_tp_gate / zip_typing_lockout 180ms
                              │ zip_tp_layer（レイヤー4）/ xy_scaler 1×2 / tpc_mode
                              ▼
                         HID マウスレポート

ジッタ対策 — 概要

  • N しきい値: 軸ごとに累積の絶対値が N に達するまで HID を出さない（デフォルト左 20、右 8。レイヤー5で変更可）。
  • ストリームモード: N に達したあと、同符号の ±1 を 1 サンプルずつ即時送出。階段状の「N 個ずつ跳ね」を解消。
  • 符号反転・アイドルでリセット: バラバラな ±1 は累積が伸びず、N 未満のまま捨てられる。
  • サンプルデッドゾーン 0: ±1 を捨てない（LPPS の正常パルスを維持）。
  • レイヤー4: 報告の絶対値が 3 未満は起動・タイムアウト延長に使わない。
  • 打鍵ロックアウト: 非修飾キー後 180 ms は相対移動を止める（入力振動ジッタ）。

ジッタ対策 — 詳細（lpps.c）

CONFIG_LPPS_JITTER_FILTER=y 時のみ有効。OFF 時は IRQ ごとに生 x/y をそのまま報告（ベンチマーク用）。

定数 / Kconfig左（既定）右（既定）役割
LPPS_ACCUM_REPORT（N） 20 8 起動前の累積しきい値。レイヤー5の Q/A・P/; で runtime 変更（1–127、settings 保存）。
LPPS_INSTANT_REPORT 12 12 1 サンプルで即時送出する幅。instant = max(INSTANT, N) のため N≥12 時は実質 N と同じ。

LPPS_SAMPLE_DEADZONE 0 0 未使用（0 のときコンパイル時にデッドゾーン分支は無効）。
LPPS_MIN_POLL_INTERVAL_MS 2 RDY 立ち下がり後の次ポーリング間隔。

軸フィルタ状態機械（lpps_filter_axis）

軸 X・Y は独立（stream_sign_x / stream_sign_y、累積も独立）。

  1. 待機（stream_sign == 0）: サンプルを符号デッドゾーン付きで累積。いつも 報告しない。
  2. |累積| ≥ N: 累積分を 1 フレームで HID 送出、ストリーム符号を設定、以降はストリームへ。
  3. ストリーム中: 同符号のサンプルはその値をそのまま 1 フレーム送出（±1 が連続すれば滑らかに動く）。
  4. 符号反転: ストリーム解除、累積リセット。反転後サンプルから再び N まで蓄積（ジッタの行ったり来たりは届かない）。
  5. 強サンプル（|sample| ≥ instant）: 即時そのサンプルを送出しストリーム開始。
アイドル境界: 前回モーションから ACCUM_IDLE_MS 超過で lpps_reset_axis_filter。 新しい窓の最初のサンプルは CLAMP(±2) のみ（大きな EMI スパイク抑制）。N 未満の部分送信は行わない。

  • min-activation-frames = 2
  • activation-window-ms = 350

ドリフト対策 — 概要

  • 手動キャリブレーション: キーマップの &ps_calib（レイヤー3・5）で LPPS レジスタ 0x04 へ書き込み要求。
  • 符号デッドゾーン（累積）: 累積と新サンプルの符号が逆なら累積を 0 に（往復の微小ドリフトを相殺）。
  • アイドルリセット: 長い無入力後は未送信累積を破棄（ゆっくり溜まったノイズを一方向に流さない）。
  • アイドル直後クランプ: 窓をまたいだ最初のサンプルを ±2 に制限（単発スパイク型の見かけドリフトを抑制）。
  • 起動時サンプル破棄: 初期化・再開後、先頭 1〜2 IRQ は読み捨て（discard_samples）。
  • IRQ レート制限: IRQ 無効化＋最小ポーリング間隔で I2C/BLE 飢餓を回避（左キースキャン欠落の再発防止）。
  • レイヤー4 純変位: 行ったり来たりのカウントが相殺されるため、微小振動だけではレイヤーが付きっぱなしにならない。

注意 本実装は一方向に永続する大きなドリフト（常に同符号で N を超え続ける）には、 ストリームモードでカーソルが動き得ます。根本はハードウェアキャリブレーションと N の調整です。 ジッタ対策（N 未満非報告）は、ランダムな ±1 には効き、一方向バイアスはキャリブレーション層で扱う設計です。
